# 证据阶梯、授权边界与所有权

读这份文件的时机：你要下一个**结论**（「这个功能能用」「没超限」「上传没问题」），或要动一个**共享资产/生成输出**，或要判断用户那句话到底授权了什么。

> 这是全套分册的**方法论底座**。任何时候拿不准「我这句话有没有证据」，就回来查第 1 节；拿不准「用户授权我到哪一步」，查第 2 节。

## 1. 七层证据阶梯

| 标签 | 能证明什么 | **不能**证明什么 |
| --- | --- | --- |
| `STATIC_SOURCE` | 序列化引用、字面值、资产身份、声明的配置 | 导入后的语义、prefab 实例解析、合并输出、运行时行为 |
| `UNITY_RESOLVED` | 当前**已导入**的对象、组件字段、激活态、prefab 覆盖，以及通过选定 Unity MCP 实例观察到的确切层级 | 最终 NDMF 输出、VRChat 运行时行为 |
| `PROVIDER_PREVIEW` | provider 可见的源清单，或虚拟/预览状态 | 后续 pass 仍可能改写它，所以不是最终 SDK 产物 |
| `NDMF_BUILT` | 注册 pass 跑完后的合并/生成头像、菜单、参数、控制器、网格、组件 | SDK bundle 限制或客户端行为（除非那些层也跑了） |
| `SDK_BUILD` | SDK 校验，以及**确切的生成 bundle 或最终参数资产** | 桌面/VR/多人/上传行为 |
| `CLIENT_RUNTIME` | 在**具名测试环境**里的行为 | 其它客户端、硬件模式、网络，或未经单独测试的上传 |
| `UPLOAD_CONFIRMED` | 明确授权上传的那个头像的**实测行为** | 未观察的客户端、后续改动 |

### 1.1 两条铁律

1. **用当前证据能支撑的最窄标签。** 别把 `PROVIDER_PREVIEW` 说成 `NDMF_BUILT`。
2. **层与层之间不可互相替代**：更新的低层结果**不能**替代旧的高层结果（比如重跑一次源检查，不能推翻之前的构建结论）；旧的高层结果也**不能**证明当前源（改过源之后，旧构建结论作废 → `STALE`）。

### 1.2 状态词表（报告里统一用这些）

- `PASS`：只有**已执行的层**且**满足验收标准**才能用；
- `NOT_RUN`：这一层**没尝试**；
- `BUILD_REQUIRED`：源级证据**无法回答**生成态的问题；
- `MCP_REQUIRED`：结论/动作需要 Unity Editor 状态，但**没有可用且确切的 Unity MCP 实例**连着；
- `BLOCKED`：尝试过，但**拿不到可靠证据**；
- `STALE`：曾经的证据被某次刷新触发**作废**；
- `AMBIGUOUS_TARGET`：构建、缓存、Pipeline Manager 身份或重复对象**无法**与唯一确定的头像关联。

**阻塞原因要写具体**：Unity MCP 实例不可用/不明确、场景 dirty、工程被锁、编译失败、缺 Unity 授权、工具抛异常、缺完成标记、目标不明确、或**没有授权**。

### 1.3 好/坏结论对照

✅ 好：

- `UNITY_RESOLVED`：选中的头像实例上有该组件，且它引用的 controller 解析到该资产。
- `PROVIDER_PREVIEW`：参数 provider 估算 228 bit；最终 SDK 成本 `NOT_RUN`。
- `NDMF_BUILT`：生成后的菜单里有这一项；桌面、VR、多人行为 `NOT_RUN`。
- `SDK_BUILD`：具名的 PC 头像构建在两个 bundle 限制之下；上传 `NOT_RUN`。

❌ 坏（**永远不要这样说**）：

- 从 YAML 或一段 Animator clip 得出「这个功能在 VRChat 里能用」；
- 从工程资产体积或一个不明确的旧缓存得出「头像没超体积限制」；
- 从层级相似得出「所有相似头像的参数成本都一样」；
- 只跑了 Build & Test 或本地预览，就说「上传通过了」。

## 2. 授权矩阵（用户的话 → 我实际能做什么）

| 用户措辞 | **通常算授权** | **不自动算授权** |
| --- | --- | --- |
| 查看、解释、审计、对比、诊断 | 读文件、检查实时状态、做**非改动性**诊断 | 保存、Apply、导入/刷新、Play 模式、构建、上传 |
| 修、改、删、迁移 | **窄范围**的源编辑、受影响的审计文档更新，以及与改动相称的导入/编译验证 | Build & Test、新做体积探针/构建、发布/上传 |
| 新增或导入功能/插件 | **窄范围**安装、源编辑、导入/编译验证，并记录菜单、参数、源占用、体积证据状态、模型职责 | 新跑 SDK 体积构建、Build & Test、发布/上传（除非另有授权） |
| 更新贴图/材质/shader/网格/视觉动画 | **窄范围**资产/源编辑、importer 验证、共享消费者审计、视觉 map 更新、源占用记录，并**作废过期的构建体积证据** | 新跑 SDK 体积构建、客户端视觉验收、发布/上传（除非另有授权） |
| 预览或测试 | **具名**的预览/运行时层及其常规可逆准备 | 上传，或顺带清理不相关的工程 |
| 构建 | 针对**确切目标**的具名构建 | 上传；破坏性源改动；假设 Build & Test 会替你检查上传限制 |
| 检查头像体积 | 读相关体积指南，为具名目标跑需要的报告/缓存探针或确切的体积构建 | 上传；或把结果套用到另一个头像 |
| 上传或发布 | 仅在 preflight 之后，**确切确认过的那一个头像与平台** | 靠猜选目标，或上传另一个活跃 descriptor |

### 2.1 必须停下来问的情况

当请求的动作**可能**：覆盖未保存的场景工作、修改共享源、或影响具名目标之外的多个消费者 —— **停下来，先去拿缺失的那个决定**。

## 3. 六类所有权边界（「可编辑源」到底在哪）

**可编辑源 = 工具期望用户改动的那个地方。** 生成结果、构建克隆、缓存是**证据或一次性产物**，不自动是编辑目标。

| 边界 | 真相所在 | 典型内容 | 安全默认 |
| --- | --- | --- | --- |
| **场景覆盖（实例）** | 确切的场景实例及其 prefab 修改 | 激活态、本地变换、增删的组件、被覆盖的引用 | 在映射它的 prefab 与消费者之后，**只改具名实例**。不要假设 prefab 资产会跟着变。 |
| **共享资产** | 被引用的资产文件 | 被多个根使用的 prefab、菜单、参数、controller、动画 clip、材质、网格、贴图 | **先映射每一个消费者。** 除非证明是隔离的，否则改动都是多消费者改动。 |
| **可编辑生成器源** | provider 组件、源 prefab、配置资产、稳定的用户 clip | FaceEmo 表情、MA 组件、库存/衣柜设置、通用功能 provider、优化器设置 | 改**该 provider 支持的那个源**，然后用它文档化的预览/重生成路径。 |
| **生成输出** | provider 生成的 controller、菜单、参数资产、合并组件、优化结果 | 带时间戳的工具输出、NDMF 结果、合并后的 Animator、优化过的网格/材质 | 可以**查看或 diff**，但不要当真相源去编辑。**从源重生成。** |
| **构建克隆** | 为预览或 SDK 构建临时做的头像克隆 | NDMF 预览克隆、SDK 构建副本、仅测试用的层级 | 当**一次性**处理。记录确切的源指纹与目标；**永远不要靠猜把改动拷回去**。 |
| **缓存** | 工具或编辑器缓存 | Library、Temp、SDK 构建缓存、provider 缓存、过期报告 | **仅诊断用。** 它可能过期，或匹配到不止一个头像，**不能**证明当前源或上传状态。 |

**所有权跟随写入路径，不跟随对象名字。** prefab 覆盖、增删组件、非激活对象、资产 GUID 都属于**它们被存储**的那个边界。一个场景覆盖仍然可以指向**共享** clip/材质；一个生成输出也可能暴露**缺失的源引用**。

## 4. 改共享资产之前：消费者映射（7 步）

在编辑共享资产、应用 provider、在 provider 之间迁移、或删除旧源之前**完成**这张图。图的范围锁定到确切的目标根/场景/prefab，但**包含每一个已知的共享文件消费者**。

1. 记录确切的目标层级路径、场景或 prefab 路径、激活态、dirty 状态、Unity 与 provider 版本、请求的结果。
2. 确定**写入所有者**属于哪一类：场景覆盖 / 共享资产 / 可编辑生成器源 / 生成输出 / 构建克隆 / 缓存。相关处记录 **GUID/fileID 与 prefab 出处**。
3. 沿 **GUID/fileID 链接与 provider 引用**枚举直接与间接消费者：descriptor 的菜单与参数、menu installer/item、merge animator、表情 clip、controller、网格、材质、贴图、constraint、PhysBone、Contact、音频、粒子，凡该功能能触及的都要列。
4. 区分**共享消费者**与**隔离副本**。**不要**用层级相似、根名字、激活态、或旧的 Pipeline Manager ID 作为「隔离」的证明。
5. 记录每个结论的**基线证据层**，以及确切生成/构建产物（如果存在）。**预览、构建、运行时测试、上传分别独立标注。**
6. 列出预期**爆炸半径**：Apply / 重生成 / 预览 / 构建之后，哪些根、prefab、菜单、参数、clip、材质或生成输出**可能变化**。
7. 在**任何破坏性移除之前**，定义恢复点与最小验收检查。**场景 dirty、未保存覆盖、目标不明确 = 停止条件**，不是猜的理由。

## 5. 迁移职责清单（换 provider 时逐项打勾）

当把一个服装/表情/功能 provider 换成另一个，**每一项职责**都要标记为「已映射 / 已重建 / 已验证」，且都要针对**确切目标**：

- [ ] 菜单路径、控件类型、默认值、页内位置、可达性；
- [ ] 参数名、类型、默认值、saved 标志、同步模式、remap、对**每个头像**预算的影响；
- [ ] Animator 层、状态、过渡、driver、clip、层顺序；
- [ ] 骨架合并、骨骼 proxy、constraint、根路径、缩放；
- [ ] 网格 renderer、子网格、材质槽、shader 属性、贴图、平台 importer 设置；
- [ ] BlendShape 名称、权重、同步规则、动画绑定路径；
- [ ] 对象开关、激活默认值、可见性、回退状态；
- [ ] PhysBone、碰撞体、Contact、sender/receiver、self/other 过滤、本地 vs 同步参数；
- [ ] 音频、粒子、灯光、constraint 及其它非视觉效果；
- [ ] 合并后的 provider 顺序、生成所有权、重复的菜单/参数声明；
- [ ] NDMF/provider 输出相对已映射职责的 **diff**；
- [ ] 具名的桌面/VR/多人或其它运行时层（按需）；
- [ ] 仅**另行授权**时才做的 SDK 构建与上传就绪性。

**只有**在替代实现已经：① 有检查过的源链；② 在要求的层上 provider/NDMF 检查通过；③ 有记录「什么被有意退役」的消费者图 —— 之后，才移除或停用旧 provider。清理后**更新这张图**，免得以后的审计把过期输出误当活跃源。

## 6. 生成输出禁改政策（含唯一窄例外）

**不要**编辑任何带时间戳或工具所有的生成输出：FaceEmo、Modular Avatar/NDMF、lilycalInventory、Dressing Tools、Avatar Optimizer、其它 provider，或 SDK 构建产物。包含生成菜单、controller、参数资产、
合并组件、优化过的网格/材质、构建克隆、缓存文件。生成输出**可以被重生成、重命名、清理或替换**，手改不是持久修复。

### 6.1 唯一窄例外（四个条件必须同时满足）

存在**显式的、有文档记录的工具移交**，声明某个特定导出是**用户可编辑且不会被重生成**的，且满足全部条件：

1. 确切产物与共享消费者**已隔离**；
2. **用户已授权**这次编辑；
3. 重生成与所有权行为**已记录**；
4. 结果被保存为**稳定源**，或作为下次构建的**有文档输入**。

任何一条缺失 → 改为**查看或 diff 该输出**，去改可编辑源。

**读取、diff、报告生成输出，永远与编辑它是两回事。**

## 7. 落地写法（每次报告都套这个骨架）

```text
目标        : <确切层级/场景/prefab 路径>
写入所有者  : 场景覆盖 / 共享资产 / 生成器源 / 生成输出 / 构建克隆 / 缓存
共享消费者  : <GUID/fileID 链路枚举结果，或「已证明隔离 + 依据」>
爆炸半径    : <Apply/重生成/构建后可能变的根/菜单/参数/clip/材质>
基线层      : STATIC_SOURCE / UNITY_RESOLVED / PROVIDER_PREVIEW / …
本次层      : <执行到哪一层，各层独立标注>
未跑层      : NOT_RUN / BUILD_REQUIRED / MCP_REQUIRED / BLOCKED
恢复点      : <备份/提交/导出路径>
```

## 8. 边界

- 本节的所有标签、状态词、授权推断都是**纪律**，不是建议。跳过它们做出的结论，等于把猜测当事实交付。
- 本机若有 Unity MCP 实例可用（编辑器已安装于 `<VRCHAT_ROOT>\tools\Unity\2022.3.22f1\Editor\Unity.exe`，需**先由用户打开工程**）才可能达到 `UNITY_RESOLVED` 及以上；连不上就一律 `MCP_REQUIRED`，**不要**把「文件里写着」当成实时状态。
