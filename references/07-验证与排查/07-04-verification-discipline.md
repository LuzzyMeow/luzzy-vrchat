# MCP 调用、分帧验证与失败处理

读这份文件的时机：**准备通过 MCP 动 Unity 之前**，以及任何一次操作「看起来没成功」「不确定有没有生效」的时候。

> 本分册规定**工具与证据纪律**，**不授权**任何未被用户许可的源资产、Play、构建或上传操作。
> 证据分层与授权判定的上位规则见 [07-02-evidence-and-ownership.md](07-02-evidence-and-ownership.md)。

## §1 原生 MCP 优先

- 优先使用宿主已暴露的 `mcp__<server>__<tool>` 工具，**不另起桥接进程**绕过实例选择、schema、超时与取消机制。
- 外部桥**并非必然每次新建连接**，但无必要时不应引入。原生工具缺失时按基底报告 `MCP_REQUIRED`；**仅在明确允许的环境**中使用已验证的长连接替代。
- ⚠️ **服务名、端口、宿主配置文件位置不是通用常量**；用当前可见 schema，**禁止照抄私有机器路径或旧会话 / instanceID**。
- 本机前提：编辑器在 `<VRCHAT_ROOT>\tools\Unity\2022.3.22f1\Editor\Unity.exe`（2022.3.22f1c1）。**必须由用户先把工程打开**，`mcp__unity__*` 才连得上；在此之前所有需要编辑器的步骤只能标 `MCP_REQUIRED`。

## §2 连接、状态与日志基线

（**做任何写入之前**先完成这一节）

1. 证明**准确的项目路径、Unity 版本、目标场景 / 层级与 prefab 来源**。支持多实例的宿主先**发现并选择**实例；单实例服务从该连接读回身份。⚠️ **无法唯一证明就停止 Editor 写入。**
2. 检查 `isPlaying` / `isPaused` / `isCompiling` / `isUpdating`、Prefab Stage、dirty、场景根、相机、Selection 与目标连接状态。
3. 控制台**分别**查看 **Error、Exception、Warning**，按时间 / 类型归组，**保留首个异常与栈**。⚠️ **`Error = 0` 不能推出无异常**；**清缓存后也不能证明修复**。
4. 工具封装适用时先用资产 / 组件窄查询；未封装的 API 用原生脚本或**经发现签名**的反射方法——**不先猜字段**。

## §3 调用成本与单一所有者

- **独立的只读查询可以并行**；跨帧的「设置 → 求值 → 截图 / 读回」**必须是不同调用**。
- **一个写入调用只处理可回滚的窄层面**，不把全场景扫描、生成与几何大循环混在一起。
- **重计算导出到项目外进程**，矢量化或按项目要求用 GPU。Unity 主线程只做短时数组导出 / 回写**并计时**；长任务用**进度 / 产物轮询**，**不在主线程 sleep 或等待后台任务**。
- ⚠️ **并行代理不能同时持有同一 Unity 场景 / 导入 / 构建的写入权。** 非幂等操作要考虑 MCP 重试，保留**输入哈希、完成标记与稳定目标**。

## §4 备份与写资产

- **依赖与所有权确定备份范围**：源文件 + `.meta`、场景覆盖、直接依赖、新增文件清单；保持源相对路径，**校验源与备份指纹**，**不要覆盖同名的不同 clip**。
- 优先用 `AssetDatabase` / `PrefabUtility` / `AnimationUtility` 等**正确 API**；保存本次目标，**单独读回**。
- 对 prefab 文件使用**本版支持的加载 / 保存方式**，记录 source / instance；⚠️ **不把场景覆盖无差别 Apply 到共享 prefab**。
- 外部文件修改后**显式 import / refresh**；没有外部写入时**不用**全工程 ForceUpdate。针对回滚优先**指定资产 ImportAsset**。
- ⚠️ **保存不保证全部成功**：另读 shape 帧、driver、motion、参数默认、对象引用 / 连接状态与文件指纹。

## §5 `script-execute` 模式

**以当前工具 schema 为准**，不把某个旧版本的约束当铁律。

- 完整代码模式提供类与 `static` 方法；可用 `public static`，`className` / `methodName` 需匹配。
- 支持 `isMethodBody=true` 的服务可只传方法体；**不支持时不能照搬**。
- 仅给方法传参数时填 `parameters` 及其名称 / 类型 / 值；常量可以直接写进代码，**空参数表不是必然失败**。
- ⚠️ **编译失败意味着该编译单元未执行；但执行异常可能已有部分落盘。** 停止重试，**核对完成到哪一步**再补做。
- 第三方字段 / 类型用实际 schema 或 `SerializedObject` 读取；⚠️ **`stringValue` 不适用于所有字段**，按 `propertyType` 读 Bool / Float / Int / Enum / ObjectReference。
- ⚠️ **Roslyn 动态类的嵌套 DTO 可能不被 Unity 序列化。** 导出后**先核对字段、数组长度与格式**再算几何；**「文件写出成功」不足以证明数据完整**。

只读代码模式示例（**工具确实支持时**）：

```csharp
using UnityEngine;
public static class Probe {
    public static string Run() { return Application.unityVersion; }
}
```

## §6 超时、失败与重试

1. 取 Editor 状态、日志、目标文件 / 对象、**完成标记**；⚠️ **超时不等于没执行**。
2. **确定没执行或只执行了一部分之后**才补做；相同失败反复出现时**缩小范围、查 schema 或停止**，**不盲连续重发**。
3. 若操作会被自动重试，使用**固定输入、幂等绝对写入与处理标记**。⚠️ **细分 / 缩放×倍率 / 追加层 / 删建 asset 都不是天然幂等。**
4. ⚠️ **文件大小稳定只是观察指标**；还要完成标记、内容清单 / 格式、checksum 或对应导入验证。**进程退出码 0 也不是语义验收。**

## §7 分开调用的验收循环

**写入 → 更新 / 求值 → 读回 / 截图 → 与基线比较**

- SMR 设权重后要**另一次调用**读回并截图；必要时请求 Editor 更新 / Scene View repaint——⚠️ **不承诺每个服务都「正好一帧」**。**同调用内渲染可能拿到尚未更新的蒙皮。**
- 固定机位、姿态、材质 / 灯光、遮挡对象、实际权重与证据层。**单独换一个确定会改变画面的变量**校验渲染链。
- 如要验证「源资产修改后的生成结果」，**需要新的生成 / 构建对象**；⚠️ **旧 Play 克隆与旧 cache 不算新验证**。

## §8 Play 规则

- **源资产在编辑模式编辑。** 仍在 Play、且本次授权不足以停止当前用户测试时**先询问**；停止后**读回确认**。
- ⚠️ **已持有授权时不因技能重复加载再问一次。** 也**不能因为「修复」就擅自上传或启动尺寸构建**。
- 临时 Play 试验在**非持久副本**上；关闭会接管值的驱动**仅用于几何隔离**。**验证菜单 / Animator / PhysBone 本身时应让相应驱动运行。**
- ⚠️ **当前 `isPlaying` 已为 true 不代表重建**；需要**真实退出 / 重新进入**（获授权）或其它等效的已验证新生成步骤。
- 结束恢复播放 / 暂停、临时对象、相机、Selection 及实验参数。**不保存临时 Play 状态**；用户授权的源修复保留。
- ⚠️ **PhysBone 静态状态 / Job 异常，不能用「关 Domain Reload 必坏」或「循环警告一定良性」跨版本推断。** 保留首个异常、对象生命周期与调度证据，**验证修改前后**；**警告存在**与**实时 Exception 刷屏**分开处理。

## §9 Prefab 与场景覆盖

- 区分 **prefab asset / prefab contents / scene instance override / 生成 clone 与 cache**。**Prefab Stage 已开或有未知 dirty 工作时先守住用户状态。**
- ⚠️ `PropertyModification.target` **通常是源 prefab 对象**；用 `GetCorrespondingObjectFromSource(instanceComponent)` 或**精确 GUID/fileID 映射**，**不直接拿 instance 组件做相等比较**。
- 比较 **源 target + propertyPath + value + objectReference**。除 enabled / Transform 外，还查 mesh 引用、`m_Bones` 数组、`m_BlendShapeWeights.Array.size` 与元素、shape 名称 / 顺序。
- ⚠️ **新增 shape 但场景仍覆盖旧数组长度时，prefab 里新 shape = 100 而场景里 = 0 是可能的。** 只移除 / 纠正**已被证实的过期覆盖**，**不用 Revert All**。
- 编辑态体型、source 默认值与 runtime 曲线采样值**分别记录**。需要同步时**只改依赖的衣服**，**不能默改身体形变 / 材质 / 开关来隐藏问题**。

## §10 交付前自检

- [ ] 目标、版本与写入范围已证明；当前**不在编译 / 导入中**。
- [ ] 每项修改有**独立读回**；状态 / driver 引用保存后仍在；**没因重试产生重复层 / shape**。
- [ ] **源 prefab 与 scene instance 都检查过**；已授权场景保存后 `isDirty=false`，文件指纹已记录。
- [ ] 原相机 / 根 / Selection 不变，**无临时对象 / 新增 Missing 脚本**；**保留未知的用户工作**。
- [ ] 记录源体积变化、构建大小证据是否 `STALE`，以及 `NOT_RUN` / `BUILD_REQUIRED` 层。

## §11 图像、BakeMesh 与预览

- **编辑 Scene View 可以反映 SMR 实际形变权重**，适合验证编辑态外观；⚠️ **与 runtime 不同不说明素材坏**，而要去找默认值 / 驱动差异。
- Play 也可能**每帧写回** SMR 值；隔离试验暂关相关驱动、设值、更新、读回、截图。⚠️ **菜单 / 表情 / PhysBone 集成测试不能关掉其被测驱动而声称通过。**
- `BakeMesh` 得到的是**蒙皮几何快照**，可用于距离 / 矩阵验证；⚠️ **它不是完整渲染上下文**。**把烘焙后的顶点又蒙皮一次**、丢材质 / 法线 / 切线 / 变换、改变剔除等都会制造假象。**不能说 BakeMesh 天然必塌或天然可靠外观。**
- 多个预览副本**必须知道来源与 driver 状态**；清理放 `finally`。判断双眉 / 红块等要**默认特写 + 对应状态对比**，**不能仅凭单图排除所有因果分支**。
- ⚠️ 预览物体 Animator 的 `runtimeAnimatorController=null` **可能由 PlayableGraph 驱动**；**未找到 controller 不等于无动画**，**更不能把 `GetFloat` 的 0 当真实参数**。

## §12 生成、参数与源引用

### §12.1 长任务完成判据

导出 / 依赖计算 / 生成操作需明确**产物清单、完整字段、成功标记 / 日志及语义读回**；⚠️ **超时或大小稳定都不独自决定成功**。缓存中间计算，回写使用**稳定输入哈希**。

### §12.2 生成层才有的最终结果

- 源 ExpressionParameters 的预算可在编辑态计算，provider 的菜单解析也可在 preview 中观察；⚠️ **它们不代表全部生成后结果**。
- 当前 SDK `CalcTotalCost()` 计**`networkSynced` 参数**（通常 Bool=1、Int/Float=8）；**`saved` 控制持久化、不控制网络预算**。以本版 API 为准；合并 / 改名 / 优化后再对**最终参数资产**复核。
- ⚠️ **自动分页属于安装的 provider / 构建后处理，不是裸 SDK 保证替任意菜单分页。** 当前 SDK 每页限制读 `MAX_CONTROLS`。
- 内部参数重命名 / 裁剪规则**按 provider 版本查**；**旧哈希格式只是实现细节**。类型、默认 / saved / synced、driver 引用与最终菜单可达性**都需复核**。
- ⚠️ **构建授权不在本技能中自动授予**；未跑新生成 / 构建时标 `BUILD_REQUIRED`，**不能把旧 cache 或时间戳当最终玩家行为**。

### §12.3 场景状态写回与覆盖差分

动画预览 / 工具操作**可能**产生场景或骨骼覆盖；⚠️ **原因要由前后对象 / 字段 diff 证明**，不能断言「所有 Play 都会这样」。

- 比 enabled、Transform、mesh、bones、blendshape 数组 / 元素与新增 / 删除组件；**target 必须映射到源对象**。
- **身体和衣服的体型变化往往由 scene 覆盖、source 默认与 runtime 曲线三处共同决定。**
- 确定问题覆盖后**只修它**，保留 provider 安装目标、blueprint ID、已接受的用户覆盖等。
- 修复获得保存授权时**在编辑态保存并读回**；⚠️ **单靠退出 Play 的内存恢复不证明磁盘干净**。

### §12.4 删参数先查引用

⚠️ **`AnimatorController.RemoveParameter()` 不会自动清理**过渡条件、driver 读写、blend tree、time / speed / mirror 参数。顺序：**递归状态机 / 子树找引用 → 编辑稳定源 → 删除声明 → 精确 grep → 获授权的生成检查**；**不是只查一层 states**。

### §12.5 Shell 辅助与路径

- **PowerShell 变量名不区分大小写**——避免覆盖保留变量或大小写近似名。
- Windows PowerShell 5.1 脚本含中文需正确编码（通常 **UTF-8 BOM**）；PowerShell 7 行为不同，**先确认版本**，不要求所有 `.ps1` 一律 BOM。
- bash / perl 替换里的 `$` 等转义按该工具处理；**写后读回**。路径含空格用 `LiteralPath` / 正确引用，**不能把 Windows 路径送成无效的 POSIX 形式**。
- 备份 / 删除 / 移动**解析绝对路径并确认范围**；⚠️ **source 不在 Git 时不可指望 Git 恢复**。

### §12.6 VRCFury / NDMF 的 Play 开关与完整性

现场读当前 **VRCFury Play 处理**、**NDMF Apply-on-Play** 与依赖 provider。⚠️ **关闭其中之一可能让预览部分功能缺失**；**缺生成物时先查日志与处理开关，不要立刻宣判素材损坏**。

⚠️ **「同一预处理顺序」不足以证明 Play 等于真实上传。** 构建报告、平台、模拟器、优化钩子与禁用配置都可能不同——**分别标注环境**。**组件被 build 剥离也不能单靠数量 0 认定没处理。**

### §12.7 第三方生成器与约束

- 用已选工具及该版本的**稳定配置**；⚠️ **不直接改时间戳生成 output**。厂商 UI 隐藏字段**尤其需要证据**，不能当预设开关乱写。
- 工具可能**实例化新骨架并删除 Setup / Dummy 对象**。⚠️ **作者侧存在的路径不一定进入最终 Avatar**；无效动画警告应在**新生成对象**中解析到**确切 path / component / property**。
- ⚠️ **避免把整个约束停用冒充某个防破选项的精确还原**——可能连带停掉正常的挤压 / 缩放。以**厂商实现与 runtime 读回**为准。
- 多次生成可能**追加重复根 / socket**；先查已生成树与日志，**非幂等按钮不盲重试**。按 provider 文档 / 源码判断，**不把某版本的字段名或合并方法当通用 API**。

## §13 网格与几何验证

### §13.1 Play 中共享网格的风险

⚠️ **`sharedMesh` 资产在 Play 里被写也可能持久化**——这不是安全的隔离实验。source 按 §8 退出 Play 后修改。临时网格用**非持久 clone**，并恢复引用 / 销毁；**读 prefab asset 不代表当前 runtime pose**。

### §13.2 回滚与重新导入

外部 Copy 可能保留 mtime；重导入指定资产后核对 **shape、权重、bindposes、索引、UV / 子网格**；必要时 mesh 数据与文件**各算一次 fingerprint**。⚠️ **仅顶点数组相同不证明法线 / shape / 权重相同。** 保留 GUID，替换 `.meta` 须有明确理由。

### §13.3 表面查询而非顶点代理

- **有限顶点采样可能漏掉面内相交**；优先**三角形重心 + 边中点**或适应性更密采样。
- ⚠️ **样本必须查询目标三角形最近点 / 相交。** 「身体面采样点 → 最近衣服顶点」**仍是顶点代理指标**，**不能标为面级穿透归零**。
- ROI / 坐标 / 状态 / 符号 / 容差**预先定义，前后同口径**。边界、开口、多层、自遮挡与退化三角**另行处理**。**有限采样只证明采样点，不保证整个表面或所有动作。**
- ⚠️ **平滑迭代数不是精度指标**；记录残差 / 退化面 / 接缝 / 轮廓与 A/B。避免 **Taubin 后按峰值放大导致整体鼓胀**；保接缝与自由边界并验证实际表面。

### §13.4 物理查询与符号限制

⚠️ **编辑模式碰撞体可能未 cook / 未更新。** 使用 `Physics.ClosestPoint` 必须验证 collider / transform 与物理步；**不可在未证实环境把返回原点解释成 0 穿透**。纯数学三角面查询可作几何验证。

⚠️ **最近面法线的有符号距离在远处、开口或错误最近层可能不可靠。** 依据预定义 ROI、法线 / 投影一致性判断；**不要按「−1 至 +3 mm 以外全丢弃」藏掉真实深穿透**。报告不可信 / 未覆盖点，**不称它们为 PASS**。

### §13.5 主线程隔离与导出格式

Unity 轻量导出矩阵 / 顶点 / 法线 / 索引 / 全部 shape / 权重；**项目外** GPU / 矢量化计算并缓存；短调用导入 → SetDirty → Save → **独立读回**。⚠️ **预先校验导出字段 / 维度**（动态 DTO 可能导出成只有 state），**避免 GPU 跑空数据**。

### §13.6 第三方内部字段

用实际 `SerializedObject` / schema 或**已发现的反射字段**，**不复制其它版本的 private 结构**。动画驱动 Aap / Float 等行为**必须核对真实参数类型**；⚠️ **Bool / Float 冲突可能使条件永远无法成立**，但**不把任何一类工具无条件命名成同一 Action 类型**。

## §14 性能、警告与日志

### §14.1 显存与 SDK 估算

⚠️ `Profiler.GetRuntimeMemorySizeLong(Texture)` 可能含 CPU 可读副本、资源 / 平台分配；**不存在通用的 2 倍比例**。区分 **runtime 内存、GPU 纹理资源与 SDK 估算**。

对 GPU 压缩纹理，可按**实际平台格式每个 mip 的块大小**求和；⚠️ **`width*height*bpp*4/3` 只是完整 mip 链的大尺寸 2D 纹理近似**——小纹理、块对齐、streaming、cubemap / array / Crunch 需另计。
SDK `AvatarPerformance.CalculatePerformanceStats` 的**签名 / 阈值现场确认**；**官方统计也不等于驱动实测 VRAM**。

renderer / material / animation 引用可产生**不同可达集合**；报告当前统计范围与**最坏状态是否测过**。**接近但不超过硬限制时不用无故要求优化**；新尺寸构建需要对应授权。

### §14.2 空层警告与删层

⚠️ **没有 motion 的层可能有 driver / LayerControl / 参数行为。** 警告提示无效动画时**先修引用、schema 或生成路径**；**删除不是唯一修法**。删除需依赖 / 行为 A/B 或明确范围与风险；**不能用「警告消失」当验收**。

### §14.3 Play 与上传不等价

⚠️ 同一 provider 可以在 Play 与上传运行**不同钩子或处理范围**；callback 顺序、某次 internal 空层与旧 bundle **不能证明永久等价**。**生成层没有 motion 也不证明无害**，保留未验证行为。

### §14.4 清日志

先保留 Error / Exception / Warning 基线与首异常证据。⚠️ **某 MCP 版本清日志曾遇到占用文件错误，但不是所有版本必失败**；用当前 tool，或发现签名后反射 `UnityEditor.LogEntries.Clear()`（**需获授权**）。**清除不修复根因。**

### §14.5 外部 scene 变化

顺序：比磁盘 fingerprint / mtime → 映射 source 对象并解覆盖集 → 按症状查 enabled / Transform / mesh / bones / shape 数组等 → **只修已证实的问题**。⚠️ **用户已实测接受的状态不拿旧备份整场景覆盖**；新 source 变更需要更新源 / 生成证据。

## §15 以实测为准

### §15.1 症状不是根因

枚举曲线、参数 provider、**所有递归 layer / state / BlendTree / driver**。**Animator / Playable 实际求值才能证明 state 与输出。** ⚠️ **层存在、clip 里的 −100、缓存 timestamp、骨名 / 平均权重、形变 max 比值，都不是生效或因果证明。**

### §15.2 更新帧与读回

设值后**结束本调用**；后续调用读当前权重与对应环境图像，必要时更新 / 禁用临时驱动。**编辑态能观察默认值；真实动作使用相应环境。** ⚠️ **不要无条件进入 Play 或关闭所有 driver 来「验收」集成行为。**

### §15.3 sanity 与输入状态

用**确定有可见变化**的变量确认渲染路径，记录当前体型、衣服、相机、实际权重与最后写者。⚠️ **若 sanity 都不变，先修测量链，不推断素材坏。**

### §15.4 已知良好参考

对比同工程中**来源、坐标、拓扑、shape / 蒙皮 / 材质相同**的参考条件。**基线与实验同机位、输入与光照**；临时对象 / 相机放**非持久 preview 场景**，完整 `finally` 清理，**检查原场景无残留**。

### §15.5 无法证明时

记录 `NOT_RUN` / `BUILD_REQUIRED` / `BLOCKED` **和具体原因**，先完成独立可证的修改；缺关键信息时给**少量明确选择与所需证据**。⚠️ **不要靠连续猜根因、改大位移、隐去失败样本或反复要求「最后一次测试」来收口。**
