# 表情曲线修复、预览图与菜单图标

读这份文件的时机：用户要求**修表情 / 换表情感觉 / 生成菜单预览图 / 换图标**，或问「表情点下去没反应」。

> 先确认**当前选定的表情工具（例如 FaceEmo）及其版本**。工具的输入、菜单、clip、纹理结构**不能跨版本照抄**；**稳定源与生成 output 必须分开**（见 [07-01-bake-and-validation.md](../07-验证与排查/07-01-bake-and-validation.md)
> 与 [07-03-provider-playbooks.md](../07-验证与排查/07-03-provider-playbooks.md)）。

## §1 先排驱动链，不把症状当素材损坏

1. 定位**具体菜单项 / 表情 → 参数 / provider → 全部最后写者**（包括 Gesture、Blink、Lip Sync、眼追踪、镜像与其它 FX 层）。枚举目标 clip 的 **Float 绑定与 ObjectReference 绑定及其关键帧**。
2. 症状「所有表情都是同一红块」可以查共享曲线 / 材质 / 默认值，**但不能仅凭它断言曲线就是唯一根因**。用同工程已知良好参考做同输入 / 同机位 A/B。
3. 读每个 shape 的**实际名称、索引、合法范围与场景覆盖**。缺曲线、写 0、多余曲线都只是**候选**；先确认当前 source 与生成/运行对象身份。
4. **只修已证实的异常曲线或源配置**；不重建整份作者 clip，**也不改 renderer 默认值去掩盖跨表情问题**——除非默认值本身已证实错误且获得授权。

## §2 修改 clip

- 先备份 clip + `.meta` 以及会生成它的配置。
- 用 `AnimationUtility.SetEditorCurve`；**对象曲线用 `SetObjectReferenceCurve`**。
- **保留未改曲线、key 切线 / 加权切线 / wrap 模式、事件与导入设置**。写入 → 保存目标 → **单独读回实际绑定与 key**（不要只信写入返回值）。类型与属性存在性现场核对。
- 若 source 改动会影响工具 clone：用**获授权的新生成 / 真实退出重进 Play** 验证。编辑态可检查 source 与静态外观；**不无条件为读曲线进 Play**，也**不把「已经有 Play 且仍为 true」叫做重建**。
- ⚠️ **生成器 owned 的 clip / menu 不要当长期修复源**；应改稳定输入，使下次生成不会丢失修改。

## §3 表情重新设计

用户说「换感觉」时，**先明确范围 / 观感目标与默认恢复方式**。组合形变可用，但**不要复制其它模型的名字 / 权重**。

核对 Blink / Lip Sync / 眼追踪与工具层是否会叠写；**各状态分帧读权重**、同机位近景对比，最后**恢复默认**。

## §4 预览纹理（FaceEmo 等工具）

- 缩略图可能是 **PNG、Texture2D 子资产或生成缓存**；先读所属 provider 与实际结构，再判断可编辑位置。
- 尺寸、格式、压缩、像素通道与行序**依当前 API / 工具而定**。⚠️ **PNG 解码行序与 Unity 像素数组可能不同**：**只在读回证明方向错误时才翻转，不能固定 flip 两次**（那会变成「猜两次」）。
- 用 Unity 纹理 / 子资产 API 与工具支持的生成接口，**不靠手猜序列化像素长度字段**。保持 **GUID / 子资产 fileID 引用**。
- Unity 导入后**读回实际引用与纹理**，检查方向、镜像、alpha、颜色空间、尺寸和可达性。**只看磁盘上的 PNG 不能证明菜单用了它。**

## §5 生成预览图

1. 明确每张图的输入：**模型 / 表情 / pose、相机、灯光、视野、实际权重、证据层**；等待相应更新完成后再拍。
2. 编辑态表情可用 Scene View；**集成 driver 行为需要对应的 Animator / 模拟器 / 客户端**。临时停 Animator 只用于**几何隔离**，**不能用来声称表情切换通过**。
3. 合理分批保存，**并检查首批的方向 / 色彩**；全部映射逐项核对，视觉抽查**明确写出抽查范围**，**不把抽查说成全覆盖**。
4. 自定义图标 / 预览要放在**稳定源或工具支持的输入**中。若生成器会覆盖手改 output，**说明原因与再生成步骤**，**不要以「用户以后不再生成」作为唯一长期方案**。

## §6 菜单图标

流程：**生成或选图 → 按项目明确路径导入 → 稳定菜单配置引用 → Unity 读回实际 Texture2D / 子资产 → 复核菜单可达性与图像**。

风格保持一致；**压缩、sRGB、alpha、尺寸按目标工具与视觉需求决定**，**不无条件复制可能不适合新图的旧 importer 设置**。

## §7 参数保存状态（saved / networkSynced）

⚠️ 两个标志**互相独立**：

- `saved = true` = 要求**客户端持久化**该参数。
- `networkSynced` = **网络同步**。

**设置 saved 不证明真实跨世界测试已通过**；状态进入 driver / 初始化 / 重复控件仍可能**覆盖保存值**。

1. 从**实际控件的 `parameter` / `subParameters` 与最终菜单**找到参数身份；**名称前缀不表示保存 / 同步**。
2. 同时检查 Descriptor 的 ExpressionParameters、MA Parameters/MenuItem、已选生成器配置及其它 provider。参数**可以在根资产声明，也可以在构建时合并**——**不能说「一定不在根资产」**。
3. 修改**拥有它的稳定源配置**，记录类型、default / saved / synced / local 与**所有写者**。**不要为了一个头像去改整个第三方包源码。**
4. 仅当旧标签包含**已不成立**的保存行为描述时才修实际生成源标签；**不要无故改 GameObject 名**（会影响动画路径）。
5. **独立读回 source 定义**；新生成后核对最终实际参数身份 / 类型 / default / saved / networkSynced 及菜单，**邻接参数不要误改**。
6. 在获授权的 VRChat 客户端设一次 → **换世界 / 重载该 Avatar** → 检查是否恢复，并说明与模拟器的边界。没测客户端就写：`saved 已配置，跨世界 NOT_RUN`。

## §8 交付

说明：改了哪个源、哪些曲线、表情 / 菜单路径、默认如何恢复、图标来源与权利、生成覆盖边界。

**分开记录** source/readback、provider preview、生成结果及**具体运行环境**；同步 / 持久测试未跑就写 `NOT_RUN`。
## §9 把 A 头像的默认表情对齐成 B 头像（本工作区实测 2026-10-24）

**需求**：让 A 的"游戏默认表情"和 B 一样，但**不能破坏共用控制器/菜单/其他头像**。

**先判定默认表情来自哪一层（按顺序查，别上来就改动画）**：

1. **Renderer 实例权重**（最常见）：`SkinnedMeshRenderer` 在场景里的**静止 BlendShape 权重**——当 FX 里负责脸的那层
   **默认状态是 Empty（空 clip）** 时，Play/上传后就是这些权重在生效。权重挂在 Renderer 实例上，**两个头像即使共用同一
   `sharedMesh` 也互不影响**。
2. **FX / Additive 层默认 state 的 clip**：若默认 state 挂着实 clip（本项目 `Kipfel_FXLayer_v1.1.1.controller` 的
   `[ USER EDIT ] Face` 层另有 `DefaultFace` 状态挂 `成品模初始表情.anim`，但**默认 state 是 Empty**），则 clip 会覆盖 1。
3. **MA BlendshapeSync / 生成器**：构建时改写权重，需同时改稳定源。

**做法（默认 state 为空时）**：读两个头像 Body SMR 的**全部形态键并集与权重** → 只把 B 的权重写到 A 的 Renderer 实例上
（不改网格资产、不改共用控制器、不改菜单/参数）→ 逐键回读确认两头像并集零差异。**改前备份场景**。

**验证（缺一不可）**：① 编辑模式渲染 A/B 头部对比图；② Gesture Manager Play 里**烘焙后**截图确认默认脸（Play 才是
MA/NDMF/VRCFury 的真实结果）；③ 全菜单回归与改动前基线逐项一致（失败项/扫描计数都要 same）。本项目实测：并集 18 键、
改 9 键（如 `mouth_smile 100→0`、`mouth_ω 0→100`、`option_pout 0→15`），Play 里显示 ω 嘴 + 腮红，162 菜单 153 PASS 与基线一致。

**边界**：默认 state 将来换成实 clip → 权重被覆盖，需改 clip/状态；上传后进游戏的实际表现 **NOT_RUN**。

**顺带：改头像根名**。Unity 动画曲线绑定的是**头像根以下的相对路径**（不含根名），MA/VRCFury/PhysBone 都是对象引用，
所以改场景根名**不需要重写任何曲线**；但**测试工具/外部脚本里按旧名查找对象必须同步改**（本项目 harness 目标名改成新名 +
包含匹配兜底），改完照样跑 GM Play 全菜单回归。
