# MA 菜单与开关实操手册

> 与基底 `../00-基底/00-02-modular-avatar.md`、本目录 `03-01-parameter-and-menu-audit.md`、`03-02-animator-menu-particles.md` 是同一主题的**第三种讲法**：
> 这里给的是**逐个组件、逐次点击的完整配方**（含参数名、勾选项、菜单挂载位置），基底与其它分册给的是**原理与边界**。三处一起看，冲突时以工程现场读回为准。
> 视频清单与来源见 `ACKNOWLEDGEMENTS.md`。

**版本提示**：教程录制时的 MA 组件名与本机版本（MA 1.14.3）可能不同（MA 1.13 起 `MergeArmature` 改名、菜单路由规则也变过）。
组件名字对不上时，按功能找（菜单项 = 装 `Menu Item`、开关目标 = 装 `Object Toggle`），不要照教程死找菜单项。

## §1 菜单优先级与「把原菜单转成 MA 形式」

### §1.1 两条优先级规则（先记这两条，再动手排菜单）

1. **角色原本的 Expressions Menu 优先于 MA 菜单**。挂在 Descriptor 的 `Expressions → Menu` 上的那份菜单，
   会排在 MA 菜单前面；MA 菜单被挤到第二页（教程实测：一层 MA 菜单被挤到第 2 页）。
2. **MA 菜单之间的顺序 = 层级列表里的上下位置**。同一父级下，排在上面的先显示；
   示例中把 `MA菜单2-3` 拖到 `MA菜单2-2` 前面，游戏里 2-3 就先出现。
   → 想调顺序就调**层级顺序**，不是调组件参数。

### §1.2 把原菜单提取成 MA 菜单（Extract Menu）

1. 选中**整个角色**（根对象）；2. 右键 → `Modular Avatar` → **`Extract Menu`**；3. 原来挂在 Descriptor 上的菜单槽
   被换成一个**新建的空 MA 菜单**（默认名 `Avatar Menu`），展开后**没有任何子项**；
4. 再对里面的项执行「**提取成部件**」；5. 之后它的结构与手搭的 MA 菜单完全一致，可直接增删改。
   （基底 `../00-基底/00-02-modular-avatar.md` 讲原理；这里的关键是**提取后原菜单槽会被空菜单替换**，别以为菜单丢了。）

### §1.3 顺手把参数也转成 MA 形式（否则两套来源并存）

1. 选中角色 → Inspector 往下滑到 `Parameters` 槽，**点一下可看当前用的是哪一份**（高亮的即当前使用）；
2. 回到 `Avatar Menu` 对象，滑到底 → 添加 **`MA Parameters`** 组件；
3. 把当前正在用的参数集**拖进「从 assets 中导入」** → 参数即注册为 MA 形式；
4. **防止与默认参数槽冲突**：新建一个空参数集——项目空白处右键 → `Create` → `VRChat` → `Avatars` → **`Expression Parameters`**，
   命名如 `Expara_PlaceHolder`；它**会自动注册 3 个新参数，把这 3 个删掉**；
5. 回到角色的参数槽，用这个空集**替换**原来的参数集；6. 运行验证各部件与开关仍正常。

> 这条与 `03-01-parameter-and-menu-audit.md` §3 的「四表面同步」对应：菜单转 MA、参数也要转 MA，
> 否则「菜单认 MA 来源、参数认旧资产」两套并存，审计时会看到同一参数两个来源。

### §1.4 预制件自带的部件菜单跑进了一级菜单：两种情况分开处理

衣服 / 玩具 / 插件预制件常自带开关，直接装到模型上时**开关会显示在一级菜单**（点 Expression 就直接看到）。
把它归位到「衣服菜单」有两种做法，看作者怎么组织：

- **情况 A：作者的 MA 组件集中在某个对象上**（整件衣服父级只有一个穿衣组件，菜单控制另起一个对象）
  → **解压缩（Unpack Prefab）** → 把**含 MA 菜单的对象**拖进你的衣服菜单下 → **移除衣服原本的 `Menu Installer`**
  → 把开关对象放回部件菜单里。
- **情况 B：参数与菜单直接装在整件衣服父级**（逐件挑开关很麻烦）
  1. 选中衣服顶层 → 找到它的 `Menu Installer` → **`Select Menu`（选择菜单）** → 展开 → 安装到你的衣服菜单；
  2. 安装后会出现一个**含 `MA Menu Install Target` 组件的对象**，它和你的部件菜单建立了链接；
  3. 再给衣服的**切换开关**加一个 `Menu Installer`，把它装到部件菜单中；
  4. **调层级顺序**，让「切换开关」排在部件菜单最前面。
- SPS / PCS（含瑟瑟类插件）同理：找到它自己的 `Menu Installer` → `Select Menu` → 装到对应菜单（作者示例装到「瑟瑟菜单」）。
- 完成后**运行验证**：两件衣服的部件菜单都归到衣服菜单下，衣服切换开关与部件同菜单，可正常使用。

### §1.5 富文本高亮按钮文字（危险选项标红）

- 把标签直接粘进**控件名称**即可生效：`<color=red>按钮文字</color>`（作者也给了加粗/斜体等富文本写法）。
- 用途：**危险或需谨慎的开关**标红提示。运行后菜单按钮即显示为红色高亮。
- 与 `04-02-expressions-and-icons.md` 的关系：那边讲**图标纹理**，这里讲**纯文本富文本**，两者可叠加。

## §2 菜单与开关的结构：一眼分辨「菜单对象」还是「开关对象」（2）

作者给的**共性辨别法**（比记组件名可靠）：

| 对象类型 | 组件组合 |
|---|---|
| **菜单（子菜单）** | `MA Menu Item`，其中 **Type = Sub Menu**，**来源 = 子对象** |
| **开关** | `MA Menu Item`，其中 **Type = Toggle**，**+ `MA Object Toggle`** |

→ **「菜单与开关的区别」就是 `Menu Item` 的 Type，以及有没有 `Object Toggle`。**

### §2.1 目标结构示例（一级菜单 → 两个子菜单 + 一个同层开关）

```
头发菜单（子菜单）
├── 原发菜单（子菜单）
│   ├── 原发发饰（开关）
│   └── 原发蝴蝶结（开关）
└── 长发菜单（子菜单）
```
（还有一个「双马尾」开关与两个子菜单**同级**。）

### §2.2 手搭步骤

1. 新建空对象命名「原发菜单」→ 加 `MA Menu Item` → **Type = Sub Menu**、**来源 = 子对象**；
2. 把原有的开关对象**拖进对应菜单对象下**（成为其子对象，菜单才会收纳它）；
3. **用 `Modular Avatar → Create Toggle` 在菜单下直接创建部件开关**：
   - 例：「原发发饰」→ 把 hairpin 拖进它的 `Object Toggle`；
   - 例：「原发蝴蝶结」→ 把 hair ribbon 拖进 `Object Toggle`；
   - **一个开关可以管多个对象**：长发蝴蝶结的 `Ribbon L` 与 `Ribbon R` **都放进同一个 `Object Toggle`**。
4. 运行验证层级与开关是否生效。

> 与 `03-02-animator-menu-particles.md` §2 的分工：那边是**多选一批物件后一键 `Create Toggle for Selection`** 的批量路线；
> 这边是**先建菜单骨架、再逐个挂开关**的手工路线。批量路线快，手工路线好控层级与顺序。

## §3 int 开关：非此即彼的换头发 / 换衣服（3）

- **语义**：int 开关 = **只选其一（非此即彼）**。用布尔开关换头发会出现「两件同时显示」的重叠（布尔是多选语义）。
- 步骤：
  1. 先把**非默认项全部隐藏**；
  2. 在角色下创建**菜单对象**（如「头发菜单」）；
  3. 其**子级**创建三个开关对象，每个加 `MA Menu Item`（Toggle）+ `MA Object Toggle`，把对应头发拖进**自己的** `Object Toggle`；
  4. **默认那一件要勾「默认启用」+「反转条件」**——因为开关的语义是「关掉」，默认启用会让本来显示的头发消失，
     勾上反转后才恢复正常显示；
  5. **三个 `Menu Item` 使用同一个参数**（示例参数名 `hairchange`）；
  6. 给**最外层菜单**加 `MA Menu Installer`，并把一个 `Menu Item`（Type = Sub Menu、来源 = 子对象）作为**安装内容**。
- **能力与成本**：**一个 int 参数占 8 槽、可取 0–255**，即一个参数实现 **256 件**物品的非此即彼切换。
  （成本口径见 `03-01-parameter-and-menu-audit.md` §1；与「如梦衣柜」的 int 是同一原理，见 `01-05` §2.4。）

## §4 换色开关：`MA Material Setter`（4）

- **硬限制**：**`MA Material Setter` 只能替换材质球（material asset），不能替换贴图**。
  → 所以要换色，必须**事先准备好不同颜色的材质球**（不是准备不同颜色的贴图）。
- 步骤：
  1. 角色下建空对象「换色菜单」；
  2. 其下建三个开关对象（蓝 / 黄 / 红），每个加 `MA Menu Item`（Toggle）+ **`MA Material Setter`**；
  3. 把要换色的**网格**（Renderer）拖进 `Material Setter` → 组件会列出 **`element 0 / 1`（材质元素索引）**；
     作者示例只替换**第 0 个元素**（颜色元素），**忽略假阴影（fake shadow）元素**；
  4. 把对应颜色的材质拖到该元素上；
  5. **三选一 ⇒ 用统一 int 参数**（示例参数名 `ear color`，视频里其实是 hair color），默认项勾**「默认启用」+「反转条件」**；
  6. 父级菜单加 `MA Menu Item`（Sub Menu、来源 = 子对象）+ `MA Menu Installer`，安装到角色。
- **与 `04-01-appearance-and-liltoon.md` 的关系**：那册讲**怎么改材质/属性**（含「renderer.material 可能生成实例」），
  这里讲**怎么把不同材质挂成菜单选项**。注意材质实例 vs 共享资产的身份问题在两处都成立。
- **与 `04-03-color-and-puppet.md` 的关系**：那册的「颜色档位」是**动画驱动的颜色/属性插值**（8-bit 写入陷阱）；
  `Material Setter` 是**整体换材质球**——不涉及数值插值，但会换掉整张材质（含其贴图与各项属性）。

## §5 形态键轮盘：`Motion Time` + `Radial Puppet`（5，胸部大小 / 百分比轮盘）

作者推荐这条路线的原因（desc 原文口径）：**参数不用到处新建、方便增减管理、不破坏 avatar 本身的动画控制器**。

### §5.1 造动画（形变 0 → 100）

1. 选中角色 → 右键创建空对象，命名「胸部控制」；
2. 打开 **Animation 窗口 → Create**，命名「胸部动画」，选保存路径 → Save（会同时生成一个控制器）；
3. 回到 Project 找到它 → 把控制器重命名为「**胸部动画控制器**」（便于辨别）；
4. **双击动画开始录制**：选中胸部所在网格（示例 `body base`）→ 点录制；
   - **第 0 帧（第 0 秒）：拉一下胸部形态键再拉回**，**确保第 0 帧值为 0**；
   - **第 0.1 秒（第 10 帧）：把胸部形态键拉到 100（最大）**；
   - 再点一次结束录制 → **取消预览**；
5. 选中动画文件 → **取消勾选 `Loop Time`**。

### §5.2 让旋钮驱动时间轴

- 双击控制器 → 图层旁边的 **Parameters → +** → 新建 **float** 参数，命名 `breast`；
- 回到图层 → 选中「胸部动画」这个状态/动画 → 勾 **`Motion Time`** → 参数选刚建的 `breast`。
  （滑块 0→1 即把动画从 0 秒播到 0.1 秒，于是形态键 0→100。）

### §5.3 用 MA 接到菜单上

1. 选中「胸部控制」→ 把**控制器拖进它的 Inspector**；
2. 加 `Modular Avatar` → **`Merge Animator`** → 把控制器拖进「要合并的 Animator」→ **路径模式 = 绝对路径**；
3. 加 **`MA Parameters`** → 添一个参数：**类型 float、名字必须与 Animator 里的参数完全一致**（`breast`）；
4. 加 **`MA Menu Item`** → **Type = `Radial Puppet`** → 参数旋钮选 `breast`；
5. 加 **`MA Menu Installer`** → 装到角色菜单；运行验证轮盘出现且可用。

> `MA Merge Animator` 的三项设置与「绝对路径」口径见 `03-02-animator-menu-particles.md` §1；
> Radial Puppet 的结构、`Motion Time` 与「跳到 100%」排查见 `04-03-color-and-puppet.md` §3。

## §6 动骨参数触发动画：拉一下就变大的呆毛（6）

**前提**：目标（呆毛）本身有 `VRCPhysBone` 组件。

1. **找到骨骼与动骨**：依次展开 脖子 → 头 → 头发骨骼（示例三根，其中 `呆毛1` 是目标）；
2. **在 PhysBone 里配置参数名**（示例 `呆毛`），并把 **`Allow Posing` 设为 true**（允许抓住后固定）——
   之后会用到「**被抓住时**」与「**被摆姿势时**」两个参数；
3. **造动画**：Animation 窗口 Create → 新建文件夹（示例 `Eku呆毛`）+ 动画名「呆毛变大」→ Save；
   录制：**第 0 帧随便拉一下**（确保有键），**第 2 帧拉到目标大小**（示例 5）→ 停止录制 → 取消预览；
4. 选中动画 → **取消 `Loop Time`**；把控制器重命名为「呆毛变大」；
5. 进控制器：Parameters 新建两个 **bool**——**`呆毛_IsGrabbed`** 与 **`呆毛_IsPosed`**
   （**命名规则 = 动骨里填的参数名 + 固定后缀**）；
6. 图层：**删掉原本的默认状态** → 新建空状态 → 把「呆毛变大」动画拖进去 → 建**进入/退出两条过渡**：
   - 进入条件：**被抓住 = true**；
   - 退出条件：**没被抓住 且 没有被固定/摆姿势**；
   - **退出时间设为 0**（手感更流畅）；
7. 回到场景：选中角色 → 创建空对象（示例「呆毛变大」）→ 加 `MA Merge Animator` → 把「呆毛变大」控制器拖进「要合并的 Animator」→ **路径模式 = 绝对路径**；
8. 测试：**鼠标左键拉动、右键固定**；松手即回到原状。

**关键结论（可复用）**：**`VRCPhysBone` 的参数后缀 `_IsGrabbed` / `_IsPosed`** 就是「被抓 / 被摆姿势」两个布尔源，
配合 `MA Merge Animator` 即可做「抓一下触发某个动画」的互动玩具（呆毛变大、耳朵扇动、尾巴翘起等同理）。
PhysBone 各组件的参数含义与预算见基底 `../00-基底/00-03-physbone-dynamics.md` 与 `07-01-bake-and-validation.md` §4。

## §7 捏脸数据：套用与反向保存（7，插件 Blend Shape to Animation）

- **插件**：**Blend Shape to Animation**，Booth 编号 **6171346**（`https://booth.pm/ja/items/6171346`）。
  导入 unitypackage 后在插件自带菜单里打开（作者示例入口在工具菜单下）。
- **面板只有两个字段**：`Skinned Mesh Renderer`（要调形态键的网格）+ `Animation Clip`（动画形式的捏脸数据）。
- **把购买/下载的捏脸动画套到脸上**：
  1. 把 `blendshape` 文件夹里的捏脸动画拖进 Unity；
  2. 网格填**脸**（示例信浓 `Body`），`Animation Clip` 填捏脸数据（示例 `base`）；
  3. 点 **`Apply animation to blend shape`** → 脸上的值即被写入（可打开 `Body` 检查已赋值）。
- **恢复原始脸型（不用逐项归零）**：
  找角色自带的**初始默认脸动画**（示例 `Shinano/Animation/FX/default face`，有的角色叫 `ideal`），
  把同一个网格 + 这个 default face 放进面板 → Apply → 所有值归零。
- **反向用途：把当前捏脸/形态键状态保存成动画**（便于备份与迁移）：
  新建动画（示例 `custom blendshape`）→ 把带捏脸数据的网格 + 刚建的动画放进面板 →
  点 **`add blend shapes to animation clip`** → 打开动画可见 `eyeclose` 等数值已录入。
- **与既有分册的边界**：`04-02-expressions-and-icons.md` §2 讲**直接写曲线**（`AnimationUtility.SetEditorCurve`）；
  这里给的是**用插件在界面上完成同一件事**的替代路线。走插件路线时仍要遵守那册的
  「写入 → 保存 → 单独读回实际绑定」纪律；**备份/迁移用的「保存为动画」产物属于生成物**，
  不要把它当源头手改（见 `07-02-evidence-and-ownership.md` §6）。

## §9 执行纪律（沿用本包通用要求）

- 上面的参数名（`hairchange` / `breast` / 呆毛 / `ear color`）都是**示例**，落地时按项目现有命名核对；**参数要统一就必须逐字一致**。
- 每个配方做完都要**运行（Play 或 Gesture Manager）验证一次**，并把结论按证据层级标注（见 `07-02-evidence-and-ownership.md` §1）；
  只把组件配好 = `UNITY_RESOLVED`，菜单真的出现且行为正确才算到运行时层。
- 涉及**预制件解压缩、删除 `Menu Installer`、改共享材质/控制器**时，先按 `07-02-evidence-and-ownership.md` §2 确认授权与所有权，
  再按 `06-02-backup-and-package.md` 留一份可回退点。
- 教程录于较早版本；**照做前先用工程里的实际组件核对**，对不上标 `STALE`，别硬找不存在的菜单项。
